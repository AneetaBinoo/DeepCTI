## 1. Why a v4 round

`results/v3/REPORT_V3.md` §4 listed open items. v4 addresses three of them:
- a pre-registered confirmation of the corrected synthesis prompt (DCv21b), which was post hoc in v3;
- a trust-estimation rule that does not discard useful scanners;
- robustness of verified extraction to misleading version strings.

It also completes the model panel:
- Mistral-Medium-3.5-128B: E5, E9 and X2V;
- GLM-4.5-Air (106B MoE): D1 E2, D7 X2 and X5. GLM-4.5-Air had been cancelled in v3 (D22).

## 3. Pre-registered results (D7 test)

| Hypothesis | Estimate [95% CI] | Rule | Verdict |
|---|---|---|---|
| **H16** DCv21b − DC claim-level note faithfulness, fresh sample (504 pairs, 70 CVEs) | +0.044 [+0.014, +0.073]; sign-flip p = 0.0046 | lower bound > −0.02 | **supported** |
| **H17** DCt − DC loss, withheld arm (n = 3,312, 70 CVEs) | −0.137 [−0.167, −0.107]; DER difference 0.000 [0, 0] | upper bound < 0 and DER upper bound ≤ 0.01 | **supported** |
| **H18** DC loss with decoys − clean (X2 baseline, as pre-registered) | −0.026 [−0.050, −0.006] | upper bound < +0.05 | supported, **but confounded** (see below) |

**H16.**
- Faithfulness: DCv21b 0.744 against DC 0.700 (2,026 and 1,914 claims).
- Note–decision consistency: 0.988 against 0.961.
- Fallback: 6.0% of DCv21b notes fell back to the deterministic template.
- Pipeline integrity: 0 replay mismatches and 0 extraction errors; 5 of 25,230 judge calls returned an error.
- The sample shares no case with the H15 sample, but 65 of its 70 CVEs overlap (V4 audit m4).

**H17.**
- DCt trusts scanners for deb-ubuntu and maven (`config/source_profiles_v3b.yaml`). For pypi the scanners'
  false-negative rate is 10.5% (Wilson upper bound 0.24 > 0.10), and for vendor software it is 100%, so DCt
  does not trust them there.
- Withheld arm: loss falls from 0.344 to 0.207 and coverage rises from 0.312 to 0.734; DER stays 0.
- Each system's decisions are identical across the 8 models, though DC and DCt differ from each other. So n
  overstates the information. The CI is CVE-clustered.

**H18 — corrected analysis (post hoc, D25).** The V4 audit (C1) found a confound. For 7 of the 8 models, the
X2 baseline ran on code from before the D21 verifier fixes. X6−X2 therefore mixes the decoy effect with a code
change: X6C − X2 for DC is about −0.026 over all decoy cases, and about −0.06 on the 46 vendor cases. X6C reruns the same cases at the prereg-v4 code without
decoys:

| contrast (X6 − X6C) | DC | DC_noverify | S3 |
|---|---|---|---|
| all decoy cases (n = 832 per system) | −0.0006 [−0.0019, 0] | 0 | −0.017 [−0.131, +0.101] |
| exposed: decoy line seen at or before the decision | −0.005 (n = 96, 3 CVEs) | 0 (n = 96) | −0.260 [−0.478, −0.025] (n = 88) |
| decoy implies a different status (93 of 104 cases: all 58 deb, 35 of 46 vendor) | 0 | 0 | +0.022 [−0.083, +0.130] |

Neither DC nor DC_noverify ever recorded a decoy version as an accepted fact. S3 records no facts, so it
has no comparable measure. Exposure was low, however (audit M1):
- DC saw the decoy before deciding in 11.5% of episodes.
- In deb cases DC reads the changelog only after deciding.
- One vendor product's decoy sits past the 8,000-character `file_read` cap.
- On multi-range CVEs, 24% of vendor decoys imply the same status as the truth (audit M2).

So H18 shows that such decoys are **inert for DC**. It does not show that the verifier resists targeted
version spoofing. The S3 "exposed" contrast conditions on a post-treatment variable (which episodes read
documents), so it is not causal.

## 5. Corrections to earlier reports (found while writing the paper; `docs/audit/PAPER_FACTCHECK.md`)

1. **ReAct is not uniformly worse than DC on D7.** Without a feed, Gemma-31B S3 has lower loss than DC:
   0.291 vs 0.344, with DER 0.047 vs 0. Without scanners the two are about equal (0.365 vs 0.344).
   `results/v3/REPORT_V3.md` reported only pooled and largest-model contrasts.
2. **D2 "upgrade without restart" ReAct losses come from two prompts.** v2 used the original prompt (S3 7.564,
   6 models). The prereg-v2 study used the v3 prompt, which states that an upgrade on disk does not fix a running
   process (S3 3.979, 9 models).
3. **DCv21's cost on drift episodes** is +34% tool cost on upgrade with restart and +79% on upgrade without
   restart (D7 X5). The "+8%" in REPORT_V3 refers to the main D7 study.
4. **The H10 gain of 0.205 is for the vendor tracker arm only.** In both feed-less D7 arms, DC equals S1′.
5. **Rounding.** `results/v2/REPORT.md` gives H2 as −0.265; the generated value is −0.26446, which rounds to
   −0.264. The paper draft also mis-rounded H1, the H10 CI and the H13 bound; those were fixed in the paper.
